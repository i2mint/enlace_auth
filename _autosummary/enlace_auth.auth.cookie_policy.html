enlace_auth.auth.cookie_policy#

Where the platform’s sign-in cookies go, in one place (#94).

Every sign-in path (password, reset, email code, passkey, OAuth, shared password) sets the same kind of cookie, and every sign-out clears it. They used to build the Set-Cookie line each on its own; CookiePolicy builds it once, so adding an attribute (Domain) cannot miss a path.

cookie_domain ([auth] cookie_domain) lets one sign-in serve apps on sibling subdomains of one parent (a.apps.example.com, b.apps.example.com, sign-in on apps.example.com): sign-in cookies then carry Domain=apps.example.com when the request came to that host or one under it. On any other host (an IP, a second name) the cookie stays host-only, as a browser would refuse the Domain there. Unset, nothing changes.

Every host under cookie_domain receives the session cookie, so it must be one the platform serves: an outside service on a sibling subdomain would see it.

>>> p = CookiePolicy(secure=True, domain="apps.example.com")
>>> p.set_header("s", "v", max_age=60, host="a.apps.example.com")
's=v; Path=/; HttpOnly; Max-Age=60; SameSite=Lax; Secure; Domain=apps.example.com'
>>> p.set_header("s", "v", max_age=60, host="10.0.0.5")
's=v; Path=/; HttpOnly; Max-Age=60; SameSite=Lax; Secure'
>>> len(p.clear_headers("s"))  # the Domain form and the host-only one
2

enlace_auth.auth.cookie_policy.absolute_next_problem(raw, domain)[source]#

None when raw is an https:// URL on domain or a host under it.

Strict on purpose: the authority must be a plain host name (an optional port), so a backslash, @ or percent sign that a browser reads differently from Python is refused, not parsed.

>>> d = "apps.example.com"
>>> absolute_next_problem("https://a.apps.example.com/x?y=1", d)
>>> absolute_next_problem("https://evil.com\\.apps.example.com/", d)
'control or ambiguous character'

enlace_auth.auth.cookie_policy.first_cookie(headers, name)[source]#

The FIRST name cookie a request carries, as the auth middleware reads it.

A browser sends the more specific (older, host-only) cookie first, and a sibling subdomain can plant a second one; Starlette’s request.cookies keeps the last. Anything that re-issues or ends “the session” must act on the one that was authenticated, which is the first.

Return type:

Optional[str]
