enlace_auth.auth.step_up#

Step-up proofs and step-up requests, independent of how the person confirmed.

A proof says “this account confirmed this action, for this audience, by this method, just now”. It is a signed token, valid for ttl seconds and spendable once. Today the passkey ceremony mints them (method="passkey"); a TOTP or an emailed code could mint them beside it without changing a redeeming backend (i2mint/enlace_auth#95).

An audience names who may redeem a proof (an app, a connector backend). A proof minted for one audience never redeems at another, and a proof minted with no audience never redeems at a backend that names one, so a backend that states its audience accepts only proofs made for it.

A request is how a backend asks for a confirmation without letting any page choose the words the proof is for. The backend signs {email, action, audience, return_url} with its audience key (audience_key(), which the operator gives it: enlace-auth step-up-key AUDIENCE) and posts it to /auth/passkeys/step-up/request; the platform answers with a request id, and the browser opens the platform’s own confirmation page for it, which shows the action and the audience. The proof binds the backend’s action and audience, and is minted once per request. A request id is signed, not encrypted: its email and action can be read from it (and from the confirmation URL, so from access logs and browser history); never put a secret in an action.

What the person SEES is guaranteed only when the platform’s pages are on an origin no app shares: on one origin, an app’s script can run the same calls as the confirmation page, or script that page, so it can still show other words while the person taps. Serve apps on their own hosts ([auth] cookie_domain) and keep /auth on the parent, with passkey origins naming only it.

>>> proofs = StepUpProofs("k" * 32, clock=lambda: 1000)
>>> act, who = "app: delete 7", "ann@x.io"
>>> minted = proofs.mint(who, act, method="passkey", audience="app")
>>> proofs.redeem(minted["proof"], act, email=who, audience="app")["method"]
'passkey'
>>> proofs.redeem(minted["proof"], act, email=who, audience="app")

enlace_auth.auth.step_up.purpose_problem(purpose, audience)[source]#

Why a backend for audience may not ask for a passkey of purpose, or None.

A purpose belongs to the audience whose name it starts with (jobs or jobs.confirm for the audience jobs), so no backend can borrow another app’s purpose passkey, and so its label, for its own action (#97).

>>> purpose_problem("jobs.confirm", "jobs") is None
True
>>> purpose_problem("jobs.confirm", "billing")
"purpose 'jobs.confirm' is not one of audience 'billing' (...)"

Optional[str]
