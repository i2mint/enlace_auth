enlace_auth.passkeys#

Passkeys (WebAuthn): sign-in, a step-up confirmation, and a per-account requirement.

Turned on by [auth.passkeys] enabled = true (py_webauthn does the WebAuthn checks). Four pieces, one boundary:

  1. Add passkeys to any account from /auth/account: several per account, each named and removable, a notice mailed on each change (/auth/passkeys/register/*, DELETE /auth/passkeys/{id}).

  2. Sign in with a passkey, including autofill on the sign-in page’s email field (/auth/passkeys/login/*). The email code stays the way back in.

  3. Step-up: an app asks the signed-in user to confirm one described action with a passkey and gets a single-use, short-lived proof that its backend (or a connector’s) redeems before acting (/auth/passkeys/step-up/*).

  4. Policy: [auth.passkeys] required lists accounts (emails, @group, @admins) that must sign in with a passkey once they have enforce_from of them. Enforced in open_session, which every sign-in path goes through.

The logic is in enlace_auth.passkeys.core (no web framework), the HTTP surface in enlace_auth.passkeys.routes, the browser side in passkeys.js (served at /auth/passkeys/passkeys.js).

class enlace_auth.passkeys.PasskeyPolicy(required, count, enforce_from=2, synced=<function PasskeyPolicy.<lambda>>)[source]#

Bases: object

Which accounts must sign in with a passkey.

required holds account keys (lower-case, every spelling already listed). The rule applies to an account once it has enforce_from passkeys, or one synced passkey (synced: it is on every device of its keychain); below that it may still sign in by its other methods, so it can enrol (a lockout guard: one lost device must not lock an account out).

>>> p = PasskeyPolicy(frozenset({"a@x.io"}), count=lambda e: 2, enforce_from=2)
>>> p.refusal("a@x.io", "password") is not None, p.refusal("a@x.io", "passkey")
(True, None)
>>> one = PasskeyPolicy(frozenset({"a@x.io"}), count=lambda e: 1)
>>> one.refusal("a@x.io", "password")  # below enforce_from: not yet
>>> p.refusal("b@x.io", "password")

Spend a step-up proof for action by email; return what it proves.

{email, action, audience, verified_at, method, passkey}. Raises PasskeyError for a forged, expired, spent, other-action, other-account or other-audience proof, one confirmed by a method outside methods, or one whose passkey has since been removed. The caller names the account it expects, so “someone confirmed” can never pass for “the owner confirmed”.

class enlace_auth.passkeys.RelyingParty(id, name, origins=tuple())[source]#

Bases: object

Who the passkeys belong to: the RP ID, its display name, accepted origins.

The RP ID is a host name every accepted origin is on or under, so one passkey covers every app served from those origins.
