enlace_auth.handles.registry#

The handle registry: which account holds which handle, kept unique under a lock.

Two mappings, each a plain MutableMapping (a dict in tests, the platform’s file store in production):

  • handles: uniqueness key -> {"handle", "account", "at", "released_at"}, public names only. A live entry has released_at None. A released one keeps the name out of reach for quarantine_seconds: after a rename it still names its old account (who may take it back, and whose old links resolve to the new name); after an account deletion its account is None (the email is erased).

  • owners: account -> {"handle", "chosen", "at", "changed_at", "previous"}. chosen is False for a private default the account has not confirmed: a frontend shows its “choose your username” step, and nobody else can see it.

A name is public only while both halves agree: a live handles entry naming the account, and the account’s chosen record naming that key. Writes are ordered so that an interrupted one leaves at most one half, which every read ignores: never two owners, never a name freed before its quarantine.

Uniqueness: every write runs under lock (a context manager). The default is a process-local threading.Lock; the platform passes file_lock(), which holds across worker processes on one host. A store with a conditional write (S3 If-None-Match, a database unique index) is the replacement for a multi-host deployment.

>>> reg = HandleRegistry({}, {}, account_exists=lambda a: True, clock=lambda: 0.0)
>>> reg.ensure("ann.lee@example.com")
{'handle': 'ann.lee', 'chosen': False}
>>> reg.ensure("annlee@example.org")["handle"]   # private defaults do not collide
'annlee'
>>> reg.claim("annlee@example.org", "Ann_Music")
{'handle': 'ann_music', 'chosen': True}
>>> reg.account_of("@annmusic")
'annlee@example.org'
>>> reg.handle_of("ann.lee@example.com") is None   # an unconfirmed default is private
True

Bases: object

Handles of accounts: assign defaults, claim, rename, release, look up.

A default handle (made from the email) is private until its account confirms or changes it: it lives only in the account’s own owners record, never in handles. So lookups, the availability check, timings and other accounts’ defaults are all unaffected by it, two accounts may hold the same private default, and confirming one is an ordinary claim that can find the name taken. A handle made from an email gives part of the address away, so it is published only by its owner’s own action (GDPR Art. 25(2); see misc/docs/research/general/usernames.md).

Parameters:

  • handles (MutableMapping) – uniqueness key -> public name entry (see the module docstring)

  • owners (MutableMapping) – account -> its handle record

  • policy (HandlePolicy) – the rules (HandlePolicy)

  • lock (Optional[Callable[[], ContextManager]]) – a zero-argument factory of a context manager held around writes

  • account_exists (Callable[[str], bool]) – whether an account exists; checked under the lock, so nothing is written for an account deleted meanwhile

  • quarantine_seconds (float) – how long a released public name stays out of others’ reach (a renamed one redirects meanwhile)

  • rename_cooldown_seconds (float) – the least time between two public names (the first choice is free)

  • clock (Callable[[], float]) – the time, in epoch seconds

claim(account, wanted, *, force=False)[source]#

Publish wanted as account’s handle (also: confirm its default).

The first public name is free; changing it waits rename_cooldown_seconds after the last change, and the old name stays with the account for the quarantine (it redirects). force (an admin) skips the reserved list, the cooldown and a quarantine, never a public owner. Raises HandleError; a taken one carries suggestions.

ensure(account, *, missing_ok=False)[source]#

The handle record of account, giving it a private default if needed.

The default is the email’s local part, then 1, 2 … until a name no one holds publicly (candidates()). A private default that someone has since published is replaced by the next one. An account that does not exist gets nothing: None with missing_ok, else HandleError no-account.

release_account(account)[source]#

Forget account’s handles (the account is being deleted); return 1 or 0.

Its public name, and the names it renamed away from, stay out of others’ reach for the quarantine with no account attached (the email is erased); then they are free. Only entries that name this account are touched, and the record goes last, so an interrupted release never frees a name early.

Return type:

int

resolve(handle)[source]#

{"handle": current} for handle, following a recent rename.

A name its account renamed away from, still in quarantine, resolves to that account’s current handle with "renamed_from"; a deleted account’s name, a private default, or an unknown one resolves to None.

>>> reg = HandleRegistry({}, {}, account_exists=lambda a: True)
>>> _ = reg.claim("a@example.com", "first")
>>> _ = reg.claim("a@example.com", "second", force=True)
>>> reg.resolve("FIRST")
{'handle': 'second', 'renamed_from': 'first'}

enlace_auth.handles.registry.make_handle_registry(handles_cfg, *, store_factory, store_root, account_exists, groups=(), lock=None)[source]#

The platform’s registry, from [auth.handles] (a HandlesConfig).

The two mappings are the platform store’s handles and handle_owners, and the lock is a flock on <store_root>/handles.lock, so the gunicorn workers of one host agree (pass lock for stores shared across hosts). The names of groups ([auth.groups]) are reserved too, so no account can be called @family.
